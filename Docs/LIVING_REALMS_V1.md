# Living Realms v1

## Mission
Turn the validated Sanctum foundation into a functional realm-based Mercury experience without weakening the existing Brain, Nexus, Memory, or dependency boundaries.

## Realm contract
- Sanctum: home/presence/invocation.
- Forge: creation, diagnostics, experiments, actions.
- Eternal Observatory: observation, system state, memory, network, temporal signals.
- Codex: deep configuration, persona, AI providers, integrations, memory controls.

## Visual contract
- No generic dashboard or tab-bar presentation.
- Realm identity is expressed through material, glyphs, ambient motion, typography, and instrument layout.
- Quicksilver remains a persistent visual presence.
- Reduced Motion must provide equivalent state communication.
- Dynamic Type and accessibility semantics are required.

## Engineering contract
- SwiftUI-native.
- iPhone 14 first.
- Keep business logic in existing services/view models.
- UI must consume MercuryBrain/Nexus/Memory through dependency injection.
- No network provider or external automation is allowed to bypass AIService or existing service boundaries.
- CI must remain green before merge.

## Sprint order
1. Forge functional realm.
2. Observatory functional realm.
3. Codex functional realm.
4. Realm transitions and shared visual primitives.
5. Accessibility/reduced-motion pass.
6. UI/navigation tests.
7. Performance audit.
8. Final CI and PR review.
